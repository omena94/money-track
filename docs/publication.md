# 發布前檢查

只公開程式、必要設定範本、migrations、合成測試、授權與通用文件。研究報告、實帳操作、設定、DPAPI、日誌、瀏覽器 profile、備份及畫面截圖均留在本機。

根目錄採 `.gitignore` 白名單；新增根目錄檔案需先評估用途。已追蹤的檔案不會因新增 ignore 規則而自動退出 Git，因此檢查器也掃描已追蹤項目。

```powershell
npm run public:check
# 初始化 Git 並準備好要提交的內容之後：
npm run public:check -- --staged
git diff --cached --stat
git diff --cached
```

第一個指令檢查 Git 候選工作檔案；若尚無 Git repository，會在 `.local` 建立暫時索引使用 Git 真正的 ignore 語意，結束後清除。第二個指令讀取暫存區實際 blob，避免工作目錄已清理但 staged 仍留有舊機密；尚未初始化 Git 時會明確失敗。

檢查器拒絕私人／產物路徑、未審核格式與符號連結，並檢查常見憑證、私人路徑、電子郵件及本機研究依賴；輸出只含檔名、行號及分類，不輸出匹配內容。銀行圖片只保留已檢視並固定雜湊的過期圖形挑戰測試 fixture；官方 App 圖像不納入公開版本。兩個既有的固定合成測試密碼採檔案及值的精確例外，不排除整份測試檔。

這是發布衛生檢查，不是完整安全稽核，也無法保證找出任意格式的個資。仍須人工檢閱實際 diff、測試資料、公開端點與授權。若未來有 Git 歷史，另行檢查歷史中的秘密；刪除工作檔不會清除歷史。不要 force-add 被排除的檔案，也不要把整個工作目錄壓縮上傳。

新 clone 必須使用自己的 Google 設定、資料庫與 DPAPI，不應複製開發者的 `.local`。本機完整資料與 Git 公開快照是不同的交付物。
